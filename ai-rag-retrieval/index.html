Retrieval-Augmented Generation (RAG)

AI-3

Introduction to RAG

Retrieval-Augmented Generation (RAG) gives a language model access to knowledge it was never trained on. Instead of memorizing facts, the model retrieves relevant chunks from your documents and uses them to answer accurately. In this tutorial you will build a real support assistant for a fictional company called Nimbus Cloud Solutions using local tools: Ollama for embeddings and generation, ChromaDB for vector storage, and Streamlit for the user interface.

Why RAG matters

  • Reduces hallucinations by grounding answers in real documents.
  • Lets you update knowledge without retraining a model.
  • Keeps private data local instead of sending it to third-party APIs.
  • Works with affordable hardware using open-source models.

What you will build

A Streamlit application that answers 100 realistic questions about Nimbus Cloud Solutions. You can toggle RAG on and off to see the difference between a model guessing from its training data and a model answering from retrieved FAQ chunks.

Chunking Strategies

Chunking splits documents into pieces that fit the embedding model and can be retrieved independently. For FAQ data, each question-answer pair is naturally a chunk. For longer documents you need to choose chunk size, overlap, and boundaries carefully.

FAQ-style chunks

Since our dataset already has short question-answer pairs, the simplest strategy is to create one chunk per pair, formatted as: 

documents = []
for item in faq:
    text = f"Question: {item['question']}\nAnswer: {item['answer']}"
    documents.append({
        "id": item["question"],
        "text": text,
        "metadata": {"category": item.get("category", "general")}
    })

print(documents[0]["text"])

Save as prepare_chunks.py and run: uv run prepare_chunks.py

Long-document chunks

For PDFs or web pages, split by paragraphs or fixed token windows with overlap: 

def chunk_text(text, chunk_size=300, overlap=50):
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start = end - overlap
    return chunks

Save as chunk_text.py and run: uv run chunk_text.py

Larger chunks preserve context but may dilute retrieval precision. Smaller chunks are precise but can lose surrounding context. Overlap helps recover boundary information.

Embeddings with Ollama

An embedding turns text into a vector of numbers so that similar texts end up close together in vector space. We will use nomic-embed-text through Ollama because it is local, free, and fast. 

import ollama

def embed(texts, model="nomic-embed-text:latest"):
    response = ollama.embed(model=model, input=texts)
    return response["embeddings"]

sample = ["How do I reset my password?", "What payment methods are accepted?"]
vectors = embed(sample)
print(f"Vector count: {len(vectors)}, dimensions: {len(vectors[0])}")

Embeddings quality check

You can verify that similar questions produce similar vectors using cosine similarity: 

import numpy as np

def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

v1 = embed(["How do I create a Nimbus account?"])[0]
v2 = embed(["How can I sign up for Nimbus?"])[0]
v3 = embed(["What is the API rate limit?"])[0]

print(cosine_similarity(v1, v2))  # high
print(cosine_similarity(v1, v3))  # low

Vector Store with ChromaDB

ChromaDB is a local vector database. It stores documents, their embeddings, and metadata, then performs fast similarity searches. Because it persists to disk, you can build the index once and reuse it across sessions.

Create and populate the collection 

import chromadb
from chromadb.config import Settings

client = chromadb.PersistentClient(
    path="chroma_db",
    settings=Settings(anonymized_telemetry=False)
)

collection = client.get_or_create_collection(name="nimbus_faq")

# Add documents in batches
batch_size = 20
for i in range(0, len(documents), batch_size):
    batch = documents[i:i + batch_size]
    ids = [d["id"] for d in batch]
    texts = [d["text"] for d in batch]
    metadatas = [d["metadata"] for d in batch]
    embeddings = embed(texts)

    collection.add(
        ids=ids,
        documents=texts,
        embeddings=embeddings,
        metadatas=metadatas
    )

print(f"Stored {collection.count()} chunks in ChromaDB")

Save as build_index.py and run: uv run build_index.py

Query the collection 

query = "How do I invite colleagues?"
query_embedding = embed([query])[0]

results = collection.query(
    query_embeddings=[query_embedding],
    n_results=3,
    include=["documents", "distances", "metadatas"]
)

for doc, dist in zip(results["documents"][0], results["distances"][0]):
    print(f"Distance: {dist:.3f}\n{doc}\n---")

Retrieval & Prompt Templates

Once you can retrieve relevant chunks, you inject them into a prompt. This is the core of RAG: the model reads the retrieved context before generating an answer. 

PROMPT_TEMPLATE = """You are a helpful Nimbus Cloud Solutions support assistant.
Use ONLY the following context to answer the user's question.
If the context does not contain enough information, say you don't know.

Context:
{context}

User question: {question}

Answer:"""

def answer_with_rag(question, k=3, model="kimi-k2.7-code:cloud"):
    query_embedding = embed([question])[0]
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=k,
        include=["documents"]
    )
    context = "\n\n".join(results["documents"][0])
    prompt = PROMPT_TEMPLATE.format(context=context, question=question)
    response = ollama.generate(model=model, prompt=prompt)
    return response["response"], context

Save as rag_answer.py and run: uv run rag_answer.py

Reranking & Evaluation

Vector search returns chunks that are semantically similar to the query, but not always the most useful ones. A reranker scores each retrieved chunk specifically for the query and reorders them. We will also add a simple evaluation harness to measure answer faithfulness.

Add a lightweight reranker

We use a cross-encoder style similarity by embedding both query and chunk, then sorting by cosine similarity. For production use, replace this with a dedicated cross-encoder like BAAI/bge-reranker-base . 

def rerank(question, retrieved_docs):
    question_vec = embed([question])[0]
    scored = []
    for doc in retrieved_docs:
        doc_vec = embed([doc])[0]
        score = cosine_similarity(question_vec, doc_vec)
        scored.append((score, doc))
    scored.sort(reverse=True)
    return [doc for _, doc in scored]

# Usage: rerank(question, results["documents"][0])

Save as rerank.py and run: uv run rerank.py

Phase 5: Full app code 

import json
import streamlit as st
import chromadb
from chromadb.config import Settings
import ollama
import numpy as np

EMBED_MODEL = "nomic-embed-text:latest"
LLM_MODEL = "kimi-k2.7-code:cloud"
DB_PATH = "chroma_db"
FAQ_PATH = "nimbus_faq.json"

st.set_page_config(page_title="Nimbus Support Assistant", layout="wide")
st.title("Nimbus Cloud Solutions Support Assistant")
st.caption("Toggle RAG on and off to see how retrieved context improves answers.")


@st.cache_resource
def load_collection():
    client = chromadb.PersistentClient(
        path=DB_PATH,
        settings=Settings(anonymized_telemetry=False),
    )
    return client.get_or_create_collection(name="nimbus_faq")


def embed(texts):
    response = ollama.embed(model=EMBED_MODEL, input=texts)
    return response["embeddings"]


def build_index():
    collection = load_collection()
    if collection.count() > 0:
        return collection

    with open(FAQ_PATH, "r", encoding="utf-8") as f:
        faq = json.load(f)

    documents = []
    for item in faq:
        text = f"Question: {item['question']}\nAnswer: {item['answer']}"
        documents.append({
            "id": item["question"],
            "text": text,
            "metadata": {"category": item.get("category", "general")},
        })

    batch_size = 20
    for i in range(0, len(documents), batch_size):
        batch = documents[i : i + batch_size]
        collection.add(
            ids=[d["id"] for d in batch],
            documents=[d["text"] for d in batch],
            embeddings=embed([d["text"] for d in batch]),
            metadatas=[d["metadata"] for d in batch],
        )
    return collection


def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))


def retrieve(question, k=5):
    collection = load_collection()
    query_embedding = embed([question])[0]
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=k,
        include=["documents", "distances", "metadatas"],
    )
    return results["documents"][0], results["metadatas"][0]


def answer_plain(question):
    response = ollama.generate(model=LLM_MODEL, prompt=question)
    return response["response"]


def answer_rag(question):
    docs, metas = retrieve(question, k=5)
    context = "\n\n".join(docs)
    prompt = f"""You are a helpful Nimbus Cloud Solutions support assistant.
Use ONLY the following context to answer the user's question.
If the context does not contain enough information, say you don't know.

Context:
{context}

User question: {question}

Answer:"""
    response = ollama.generate(model=LLM_MODEL, prompt=prompt)
    return response["response"], docs, metas


build_index()

question = st.text_input("Ask a question about Nimbus:", "How do I reset my password?")
use_rag = st.toggle("Use RAG", value=True)

if st.button("Answer"):
    if use_rag:
        answer, docs, metas = answer_rag(question)
        st.success(answer)
        with st.expander("Retrieved context"):
            for i, doc in enumerate(docs, 1):
                st.write(f"**Chunk {i}** ({metas[i - 1].get('category', 'general')})")
                st.write(doc)
    else:
        answer = answer_plain(question)
        st.info(answer)
        st.write("_No context retrieved. The model answered from its training data only._")
