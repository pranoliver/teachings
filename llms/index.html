3. How LLMs Work

What is an LLM? A Large Language Model is a neural network trained to predict the next token (word fragment) in a sequence. By doing this on billions of examples, it learns grammar, facts, reasoning patterns, and many human tasks.

Real-world example: When you type "Write a Python function to reverse a string" into ChatGPT, the model does not search the internet. It generates one token at a time based on patterns learned during training, producing code that statistically matches the request.

LLMs have three core behaviors you should understand before writing applications.

  • Next-token prediction: The model outputs a probability distribution over possible next tokens and samples from it. This is why the same prompt can give slightly different answers.
  • Pre-training: The model is trained on vast public text to learn language and world knowledge.
  • Fine-tuning / RLHF: After pre-training, models are aligned to be helpful, harmless, and honest through human feedback.
Concept Simple analogy Practical impact
Parameters Knobs the model can tune More parameters usually mean more knowledge and reasoning, but also higher cost.
Temperature Creativity dial Lower values = more deterministic; higher = more random.
Context window Working memory Maximum tokens the model can see at once; long docs must be chunked.
Hallucination Confident guess The model may invent facts; verify outputs for high-stakes tasks.

4. Tokenization & Context Windows

What is tokenization? Tokenization splits text into sub-word pieces called tokens. LLMs do not read words directly; they read tokens. Some words are one token, others are split into several.

Real-world example: "ChatGPT" might become [ Chat , G , PT ]. Knowing token count matters because APIs charge per token and models have a context limit.

Use tiktoken to count tokens locally before sending requests. 

import tiktoken

# GPT-4o uses the o200k_base tokenizer
encoder = tiktoken.get_encoding("o200k_base")

text = "Large language models learn patterns from massive text datasets."
tokens = encoder.encode(text)

print(f"Text length: {len(text)} characters")
print(f"Token count: {len(tokens)}")
print(f"Tokens: {tokens[:20]}")
print(f"Decoded back: {encoder.decode(tokens)}")

# Estimate cost for a chat session
input_price_per_1m = 2.50  # USD for GPT-4o
output_price_per_1m = 10.00
input_tokens = 1000
output_tokens = 300
cost = (input_tokens / 1e6 * input_price_per_1m +
        output_tokens / 1e6 * output_price_per_1m)
print(f"Estimated cost: ${cost:.4f}")

5. Prompt Engineering

What is prompt engineering? It is the craft of writing instructions so the model produces the output you want. A better prompt often beats a bigger model.

Real-world example: A support chatbot given "Answer the question" will be vague. Given a detailed system prompt with tone, format, fallback rules, and example answers, it becomes reliable enough for customers.

Apply these proven patterns.

  • Be specific: "Summarize this for a non-technical executive in three bullets" beats "Summarize this."
  • Use system prompts: Set role, constraints, and output format in the system message.
  • Show, don't just tell: Include one-shot or few-shot examples of input → output pairs.
  • Chain of thought: Ask the model to explain its reasoning before giving the final answer.
  • Structured output: Request JSON, XML, or markdown tables when downstream code needs to parse the result. 
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

system_prompt = """You are a polite customer-support assistant for an electronics store.
Rules:
- Answer only from the provided knowledge base.
- If the answer is unknown, say "I don't have that information" and offer to connect a human.
- Keep responses under 80 words.
- Format the final answer as a JSON object with keys: "answer", "needs_human" (boolean)."""

few_shot_examples = [
    {"role": "user", "content": "My order #12345 has not arrived."},
    {"role": "assistant", "content": '{"answer": "I see order #12345 is out for delivery and should arrive today.", "needs_human": false}'},
]

user_question = "Does the XPhone 15 support wireless charging?"
messages = [{"role": "system", "content": system_prompt}]
messages.extend(few_shot_examples)
messages.append({"role": "user", "content": user_question})

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    temperature=0.2,
    response_format={"type": "json_object"},
)

print(response.choices[0].message.content)
print("Tokens used:", response.usage.total_tokens)

6. API Integration

What is an LLM API? Providers expose models over HTTPS with a chat-completions endpoint. You send messages, the model replies, and you pay for input plus output tokens.

Real-world example: A travel app sends the user's query "Find me a 4-day itinerary for Tokyo" to the OpenAI API, then parses the returned JSON to render cards for flights, hotels, and activities.

The same request pattern works for OpenAI, Anthropic, and most OpenAI-compatible endpoints. Only the client class and model name change. 

import os
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))

message = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    temperature=0.5,
    system="You are a concise coding tutor. Explain code in two sentences.",
    messages=[
        {"role": "user", "content": "What does list comprehension do in Python?"}
    ],
)

print(message.content[0].text)
print("Input tokens:", message.usage.input_tokens)
print("Output tokens:", message.usage.output_tokens)

7. Model Selection

How do you pick a model? Balance capability, speed, cost, and privacy. The most powerful model is rarely the best choice for every task.

Real-world example: A code assistant might use GPT-4o for complex refactoring but GPT-4o-mini or Llama 3.1 for simple autocomplete, cutting API spend by 90% while keeping latency low.

Model family Strengths Best for
GPT-4o / GPT-4o-mini Versatile, fast, great tool use General apps, agents, JSON output
Claude 3.5 Sonnet Long context, coding, reasoning Analysis, code review, long docs
Llama 3 / Mistral Open weights, self-hostable On-premise, privacy, cost control
Fine-tuned small models Specialized, cheap, fast Classification, extraction, narrow tasks

9. LLM Agents & Tools

What is an LLM agent? An agent is an LLM looped with tools. The model decides which tool to call, observes the result, and either calls another tool or answers the user.

Real-world example: A coding agent receives "Fix the login bug". It uses a file-search tool, reads the relevant code, writes a patch, runs tests with a shell tool, and returns the final diff.

Below is a minimal agent with two tools: a calculator and a date lookup. 

import os
import json
import math
from datetime import datetime
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

def calculator(expression: str) -> str:
    try:
        return str(eval(expression, {"__builtins__": {}}, {"math": math}))
    except Exception as e:
        return f"Error: {e}"

def today() -> str:
    return datetime.now().isoformat()

tools = [
    {
        "type": "function",
        "function": {
            "name": "calculator",
            "description": "Evaluate a safe math expression.",
            "parameters": {
                "type": "object",
                "properties": {"expression": {"type": "string"}},
                "required": ["expression"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "today",
            "description": "Return the current ISO date and time.",
            "parameters": {"type": "object", "properties": {}},
        },
    },
]

messages = [{"role": "user", "content": "What is 128 times 17 plus today's date?"}]
response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    tools=tools,
    tool_choice="auto",
)

message = response.choices[0].message
messages.append(message)

if message.tool_calls:
    for call in message.tool_calls:
        fn_name = call.function.name
        args = json.loads(call.function.arguments)
        result = globals()[fn_name](**args)
        messages.append({
            "tool_call_id": call.id,
            "role": "tool",
            "name": fn_name,
            "content": result,
        })

final = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
print(final.choices[0].message.content)

10. Safety, Bias & Guardrails

Why do guardrails matter? LLMs can produce harmful, biased, or factually wrong outputs. Production systems need layers of defense: system prompts, output filtering, human review, and monitoring.

Real-world example: A public-facing customer bot is instructed never to provide medical advice. If the user asks about symptoms, the model responds with a prepared disclaimer and suggests contacting a professional.

  • System prompt guardrails: Explicitly forbid disallowed topics and define escalation behavior.
  • Output moderation: Use classifiers or keyword checks before displaying generated content.
  • Input sanitization: Detect prompt injection attempts such as "ignore previous instructions".
  • Rate limiting: Prevent abuse and control cost spikes.
  • Human-in-the-loop: Require approval for high-stakes actions like refunds or data deletions.

11. Production Considerations

What changes when you go to production? Prototypes are fun; production systems must be reliable, observable, cost-controlled, and fast. You need retries, caching, logging, and fallbacks.

Real-world example: A startup's AI writing tool caches common outlines so it does not pay for the same generation twice. It also falls back to GPT-4o-mini if GPT-4o is rate-limited, keeping the app responsive. 

import hashlib
import time
from functools import lru_cache

# Simple cache for deterministic prompts
@lru_cache(maxsize=1000)
def cached_summary(prompt: str, model: str = "gpt-4o-mini") -> str:
    # In real code, call the LLM API here
    time.sleep(0.2)
    return f"Summary of: {prompt[:40]}..."

def robust_call(prompt: str, max_retries: int = 3) -> str:
    for attempt in range(max_retries):
        try:
            return cached_summary(prompt)
        except Exception as e:
            if attempt == max_retries - 1:
                return "Sorry, the service is temporarily unavailable."
            time.sleep(2 ** attempt)

print(robust_call("Explain neural networks in one paragraph."))
print(robust_call("Explain neural networks in one paragraph."))  # cached

12. Capstone Project: Build an AI Writing Assistant

You are building DraftSmith , an AI writing assistant for a content marketing team. The tool must generate blog outlines, expand them into sections, and let the team review before publishing.

1. What is this project?

DraftSmith is an end-to-end LLM application that turns a one-line topic into a structured blog outline, expands each section into prose, and supports a human review loop. It demonstrates everything you have learned about prompting, model selection, structured output, streaming, local inference, and production-like robustness.

2. What it covers?

  • System prompts, few-shot examples, and JSON response formatting.
  • Calling OpenAI, Anthropic, and Ollama models through one flexible client.
  • Streaming output so writers see drafts appear in real time.
  • A self-review loop where the model critiques and revises its own draft.
  • A Streamlit UI that non-technical teammates can use in the browser.
  • Export to Markdown for publishing workflows.

3. How it is done?

Step A: Install Streamlit

Streamlit is a Python framework that turns scripts into shareable web apps. You will use it for the interactive demo.

streamlit --version

Run after installing the project dependencies from Section 2.

Step B: Core library code

Put the shared outline generator, section expander, and review loop in a module so both the CLI and the UI can reuse them. 

import os
import json
from typing import Iterable
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

cloud_client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))
local_client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

def get_client(use_local: bool = False):
    if use_local:
        return local_client, "kimi-k2.7-code:cloud"
    return cloud_client, "gpt-4o-mini"

def generate_outline(topic: str, use_local: bool = False) -> dict:
    client, model = get_client(use_local)
    system = """You are a content strategist. Return JSON only.
Format: {"title": "...", "sections": [{"heading": "...", "bullet_points": [...]}], "key_takeaways": [...]}"""
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": f"Create a detailed blog outline for: {topic}"},
        ],
        response_format={"type": "json_object"},
        temperature=0.4,
    )
    return json.loads(response.choices[0].message.content)

def expand_section(heading: str, bullet_points: list[str], topic: str, use_local: bool = False) -> str:
    client, model = get_client(use_local)
    system = """You are a technical blog writer. Write 200-250 words for the given section.
Start with a strong opening sentence and include one practical example.
Do not use subheadings inside the section."""
    prompt = f"Topic: {topic}\nSection: {heading}\nBullet points: {bullet_points}"
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": prompt},
        ],
        temperature=0.5,
        max_tokens=600,
    )
    return response.choices[0].message.content

def review_draft(draft: str, use_local: bool = False) -> str:
    client, model = get_client(use_local)
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": "You are a strict editor. List 3 concrete improvements for the draft below."},
            {"role": "user", "content": draft},
        ],
        temperature=0.3,
        max_tokens=400,
    )
    return response.choices[0].message.content

def revise_draft(draft: str, critique: str, use_local: bool = False) -> str:
    client, model = get_client(use_local)
    response = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": "Revise the draft using the critique. Keep the same length and tone."},
            {"role": "user", "content": f"Draft:\n{draft}\n\nCritique:\n{critique}"},
        ],
        temperature=0.4,
        max_tokens=800,
    )
    return response.choices[0].message.content

def stream_draft(heading: str, bullets: list[str], topic: str, use_local: bool = False) -> Iterable[str]:
    client, model = get_client(use_local)
    system = """You are a technical blog writer. Write 200-250 words for the given section.
Start with a strong opening sentence and include one practical example."""
    prompt = f"Topic: {topic}\nSection: {heading}\nBullet points: {bullets}"
    stream = client.chat.completions.create(
        model=model,
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": prompt},
        ],
        temperature=0.5,
        max_tokens=600,
        stream=True,
    )
    for chunk in stream:
        token = chunk.choices[0].delta.content
        if token:
            yield token

Step C: CLI wrapper

Build a command-line entry point that accepts a topic, picks the model, saves the outline, and prints the expanded article. 

import json
import argparse
from pathlib import Path
from draftsmith_core import generate_outline, expand_section, review_draft, revise_draft

parser = argparse.ArgumentParser(description="DraftSmith CLI")
parser.add_argument("topic", help="Blog topic")
parser.add_argument("--local", action="store_true", help="Use local Ollama model")
parser.add_argument("--output", default="article.md", help="Output Markdown file")
args = parser.parse_args()

outline = generate_outline(args.topic, use_local=args.local)
print(f"Title: {outline['title']}\n")

full_article = [f"# {outline['title']}\n"]
for section in outline["sections"][:3]:
    draft = expand_section(section["heading"], section["bullet_points"], args.topic, use_local=args.local)
    critique = review_draft(draft, use_local=args.local)
    final = revise_draft(draft, critique, use_local=args.local)
    full_article.append(f"## {section['heading']}\n{final}\n")

full_article.append("\n## Key Takeaways\n")
for point in outline["key_takeaways"]:
    full_article.append(f"- {point}")

Path(args.output).write_text("\n".join(full_article), encoding="utf-8")
print(f"Saved article to {args.output}")
print(f"Model used: {'Ollama (kimi-k2.7-code:cloud)' if args.local else 'OpenAI (gpt-4o-mini)'}")

4. What did we learn from this capstone project?

  • A clear system prompt plus a JSON schema is enough to get structured, parseable outlines from any model.
  • Streaming improves perceived speed and makes interactive UIs feel alive.
  • The same core logic can power both a CLI and a web UI when separated into a module.
  • Local models (via Ollama) let you prototype without API costs or leaving your machine.
  • A critique-and-revise loop meaningfully improves drafts and mirrors real editorial workflows.

5. How can I enhance this project in the future?

  • Add retrieval-augmented generation (RAG) so drafts cite company style guides and prior blog posts.
  • Integrate image generation (DALL·E / Stable Diffusion) to auto-create featured images.
  • Add user accounts and a persistence layer (SQLite or PostgreSQL) to save projects.
  • Implement A/B testing: compare headline variants and measure click-through rates.
  • Deploy the Streamlit app to Streamlit Cloud, Hugging Face Spaces, or a container on your own server.
