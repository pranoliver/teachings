Linux Command Line for Beginners

Chapter 1

Introduction

The Linux command line is one of the most powerful tools in software development. It is the standard interface for servers, containers, cloud instances, and embedded systems. Mastering it makes you faster and more confident in almost every technical role.

Before you start

  • A terminal (Terminal.app on macOS, WSL or Git Bash on Windows, or any Linux terminal)
  • No prior programming or Linux experience is required

What you'll learn

  • ✓ Navigate the filesystem
  • ✓ Manage users and permissions
  • ✓ Work with text, pipes, and filters
  • ✓ Control processes and services
  • ✓ Install and manage packages
  • ✓ Connect to remote servers with SSH

More practice ideas

  • Write a script that backs up a folder every day with a timestamped archive.
  • Set up a small web server (like Nginx) and inspect its logs.
  • Create a cron job that reminds you to commit your code each evening.

Chapter 2

The Terminal

A terminal is a text-based interface to the operating system. You type commands, and the shell — the command interpreter — translates those commands into instructions for the computer.

How a command flows

# Open a terminal
# macOS:    Terminal.app or iTerm2
# Windows:  WSL, Git Bash, or PowerShell
# Linux:    Ctrl + Alt + T

# See which shell you are running
echo $SHELL

# Print the current user and hostname
whoami
hostname

Checkpoint

Open your terminal, run echo $SHELL, and note whether you are using Bash, Zsh, or another shell.

Chapter 3

Navigating Files

Everything in Linux is a file. Directories are just special files that contain lists of other files. These commands let you move around and manipulate the filesystem.

# Print working directory
pwd

# List files
ls
ls -la           # all files, long format
ls -lh           # human-readable sizes

# Change directory
cd /home
cd ~             # home directory
cd ..            # parent directory
cd -             # previous directory

# Create files and directories
touch notes.txt
mkdir projects
mkdir -p projects/web/app

# Copy, move, delete
cp notes.txt notes-backup.txt
mv notes-backup.txt archive/
rm notes.txt
rm -r projects/old   # recursive delete

# Find files
find . -name "*.js"
find /var/log -type f -mtime -7

Path shortcuts

~
Your home directory.
.
Current directory.
..
Parent directory.
-
Previous directory.

Chapter 4

File Permissions

Linux is multi-user by design. Permissions control who can read, write, or execute a file. Understanding them is essential for security and troubleshooting.

# View permissions
ls -l

# Example output:
# -rw-r--r-- 1 alex staff 1234 Oct  3 09:00 notes.txt
# drwxr-xr-x 2 alex staff 4096 Oct  3 09:00 projects

# Change permissions
chmod 755 script.sh      # rwxr-xr-x
chmod u+x script.sh      # add execute for owner
chmod g-w file.txt       # remove write for group

# Change ownership
sudo chown root:root important.conf
sudo chown -R $USER:$USER ~/projects

Permission notation

Symbol Meaning Numeric value
rRead4
wWrite2
xExecute1

Chapter 5

Users & Groups

Linux separates users and groups so that multiple people can safely share the same system. Most daily work happens as a normal user, with sudo used for administrative tasks.

# Show current user
whoami
id

# Switch to root (not recommended for daily use)
sudo -i

# Create a new user
sudo adduser devuser
sudo usermod -aG sudo devuser

# Change your password
passwd

# Add user to a group
sudo usermod -aG docker $USER
newgrp docker

Checkpoint

Run id and identify your username, user ID, and group memberships.

Chapter 6

Working with Text

Linux treats text as a first-class citizen. Pipes let you chain small, focused tools into powerful workflows.

# View file contents
cat file.txt
less file.txt          # scrollable
head -n 20 file.txt    # first 20 lines
tail -n 20 file.txt    # last 20 lines
tail -f /var/log/syslog  # follow live updates

# Search text
grep "error" logs.txt
grep -i "warning" logs.txt
grep -r "TODO" src/

# Count words, lines, bytes
wc -l file.txt

# Sort and remove duplicates
sort names.txt | uniq
sort names.txt | uniq -c

# Stream editor: replace text
sed -i 's/old/new/g' file.txt

# Extract columns
awk '{print $1, $3}' file.txt

# Chain tools with pipes
cat access.log | grep "404" | awk '{print $1}' | sort | uniq -c | sort -nr | head -10

The Unix philosophy

Write programs that do one thing and do it well. Write programs to work together. Write programs to handle text streams, because that is the universal interface.

Chapter 7

Processes

Every running program is a process. Linux gives you tools to list, inspect, control, and terminate them.

# List processes
ps aux
ps aux | grep nginx

# Interactive process viewer (install with: sudo apt install htop)
htop

# Find process by name
pgrep -a node

# Kill a process by PID
kill 1234
kill -9 1234      # force kill
killall node      # kill all processes named node

# Run a process in the background
sleep 60 &

# Bring a background job to foreground
fg %1

# Send a running foreground job to background
# Press Ctrl+Z, then type:
bg %1

Chapter 8

Package Management

Package managers install, update, and remove software. The exact command depends on your Linux distribution.

Debian / Ubuntu (apt)

sudo apt update
sudo apt upgrade
sudo apt install nginx
sudo apt remove nginx
sudo apt autoremove

RHEL / CentOS / Fedora (dnf/yum)

sudo dnf update
sudo dnf install nginx
sudo dnf remove nginx
# Search for a package
apt search python3

# Show package details
apt show nginx

# List installed packages
apt list --installed

Chapter 9

Networking

Linux servers are usually headless and remote. Networking commands help you diagnose connectivity, inspect interfaces, and debug services.

# Network interfaces and IP addresses
ip addr
ip link

# Routing table
ip route

# Test connectivity
ping google.com
curl -I https://example.com

# DNS lookup
nslookup example.com
dig example.com

# Show open ports and listening services
ss -tlnp
netstat -tlnp   # older systems

# Download files
curl -O https://example.com/file.zip
wget https://example.com/file.zip

Checkpoint

Run ip addr to see your network interfaces, then ping google.com to verify internet connectivity.

Chapter 10

SSH & Remote Servers

SSH (Secure Shell) is how you log into remote Linux machines securely. It is the standard for managing servers, containers, and cloud instances.

# Generate an SSH key pair
ssh-keygen -t ed25519 -C "your_email@example.com"

# Copy your public key to a server
ssh-copy-id user@server.example.com

# Log into a remote server
ssh user@server.example.com

# Run a single command remotely
ssh user@server.example.com "uptime"

# Copy files to/from a server
scp file.txt user@server.example.com:/home/user/
scp -r user@server.example.com:/var/log ./logs-backup

# Use rsync for efficient sync
rsync -avz ./local-folder/ user@server:/remote/folder/

SSH best practices
  • Use key-based authentication, not passwords.
  • Disable root login over SSH on servers.
  • Use a non-standard port or fail2ban to reduce brute-force attempts.
  • Keep your private keys private and never share them.

Chapter 11

Shell Scripting

A shell script is a text file containing multiple commands that can be executed together. Scripts are perfect for automation, backups, deployment, and system maintenance.

#!/bin/bash

# backup.sh - backs up the home directory

SOURCE_DIR="$HOME/projects"
BACKUP_DIR="$HOME/backups"
DATE=$(date +%Y-%m-%d-%H%M%S)
ARCHIVE="$BACKUP_DIR/backup-$DATE.tar.gz"

mkdir -p "$BACKUP_DIR"

echo "Starting backup of $SOURCE_DIR..."
if tar -czf "$ARCHIVE" "$SOURCE_DIR"; then
  echo "Backup created: $ARCHIVE"
else
  echo "Backup failed" && exit 1
fi
# Make the script executable
chmod +x backup.sh

# Run it
./backup.sh

# Or run with bash directly
bash backup.sh

Chapter 12

Services & Systemd

Long-running background processes are called services. On most modern Linux distributions, systemd manages services, timers, and system startup.

# Check service status
sudo systemctl status ssh

# Start, stop, restart, enable a service
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx
sudo systemctl enable nginx    # start on boot
sudo systemctl disable nginx   # do not start on boot

# View logs
sudo journalctl -u nginx
sudo journalctl -u nginx -f    # follow logs

# Reboot or shutdown
sudo reboot
sudo shutdown now

Checkpoint

Check the status of the SSH service with sudo systemctl status ssh (or sshd on some systems). Inspect its recent logs with journalctl.

Chapter 13

Environment Variables

Environment variables store configuration that programs can read at runtime. They are used for secrets, paths, locale settings, and application config.

# View all environment variables
env

# View a specific variable
echo $HOME
echo $PATH

# Set a variable for the current session
export API_KEY="abc123"

# Add a directory to PATH
export PATH="$HOME/.local/bin:$PATH"

# Make variables persistent by adding them to ~/.bashrc or ~/.zshrc
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

Common variables

  • HOME — your home directory.
  • PATH — directories searched for executable commands.
  • USER — current username.
  • SHELL — path to your login shell.
  • EDITOR — default text editor.
