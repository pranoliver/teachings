Chapter 2

Why SQL?

SQL (Structured Query Language) is the standard way to interact with relational databases. It is declarative: you describe what you want, and the database engine figures out how to retrieve it efficiently.

Relational database structure

Why PostgreSQL?

  • Open-source, reliable, and battle-tested in production.
  • Supports advanced features: JSON, window functions, CTEs, full-text search.
  • Excellent documentation and a huge community.
  • The SQL you learn here transfers easily to MySQL, SQLite, SQL Server, and Oracle.

Chapter 3

Setting Up PostgreSQL

You can install PostgreSQL locally or use Docker for a quick, isolated environment. The examples in this tutorial assume a database named online_store and a user named store_admin .

Option A: Local install 

# macOS (Homebrew)
brew install postgresql@16
brew services start postgresql@16
# Ubuntu / Debian
sudo 
apt update
sudo 
apt install postgresql postgresql-contrib
sudo systemctl start postgresql
# Connect as postgres user
psql -U postgres

Option B: Docker 

docker run -d --name pg \
-e POSTGRES_USER=store_admin \
-e POSTGRES_PASSWORD=secret123 \
-e POSTGRES_DB=online_store \
-p 5432:5432 \
postgres:16-alpine
# Connect
docker exec -it pg 
psql -U store_admin -d online_store
-- Create the database and user (run as postgres superuser)
CREATE DATABASE online_store;
CREATE USER store_admin WITH PASSWORD 'secret123';
GRANT ALL PRIVILEGES ON DATABASE online_store TO store_admin;
-- Useful psql commands
\c online_store      -- connect to database
\dt                  -- list tables
\d customers         -- describe table
\q                   -- quit

Checkpoint

Get PostgreSQL running, connect with psql or Docker, create the online_store database, and run \c online_store .

Chapter 5

Creating Tables (DDL)

Data Definition Language (DDL) creates and modifies tables, indexes, and constraints. Below is the complete schema for the sample store. 

-- Connect to the database
\c online_store;
CREATE TABLE customers (
    id SERIAL PRIMARY KEY,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) NOT NULL CHECK (price >= 0),
    stock_quantity INTEGER NOT NULL DEFAULT 0 CHECK (stock_quantity >= 0),
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    customer_id INTEGER NOT NULL REFERENCES customers(id) ON DELETE CASCADE,
    order_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status VARCHAR(50) DEFAULT 'pending' CHECK (status IN ('pending', 'shipped', 'delivered', 'cancelled'))
);
CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    product_id INTEGER NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    quantity INTEGER NOT NULL CHECK (quantity > 0),
    unit_price DECIMAL(10, 2) NOT NULL
);

Key data types

SERIAL
Auto-incrementing integer primary key.
VARCHAR(n)
String up to n characters.
TEXT
Unlimited-length string.
DECIMAL(p, s)
Exact numeric for money.
TIMESTAMP
Date and time.
BOOLEAN
true / false value.

Chapter 6

CRUD Operations

CRUD stands for Create, Read, Update, Delete — the four basic operations on data. We will seed the sample store with realistic data. 

-- CREATE: insert data
INSERT INTO customers (first_name, last_name, email)
VALUES
    ('Alice', 'Johnson', 'alice@example.com'),
    ('Bob', 'Smith', 'bob@example.com'),
    ('Carol', 'White', 'carol@example.com');
INSERT INTO categories (name)
VALUES ('Electronics'), ('Books'), ('Clothing');
INSERT INTO products (name, description, price, stock_quantity, category_id)
VALUES
    ('Wireless Headphones', 'Noise cancelling over-ear', 199.99, 50, 1),
    ('SQL Mastery Book', 'Advanced database design', 49.99, 120, 2),
    ('Denim Jacket', 'Classic blue denim', 89.50, 30, 3);
INSERT INTO orders (customer_id, status)
VALUES (1, 'delivered'), (2, 'shipped'), (1, 'pending');
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
VALUES
    (1, 1, 1, 199.99),
    (1, 2, 1, 49.99),
    (2, 3, 2, 89.50),
    (3, 1, 1, 199.99);
-- READ: query data
SELECT * FROM customers;
SELECT first_name, email FROM customers WHERE id = 1;
-- UPDATE: modify data
UPDATE products
SET stock_quantity = stock_quantity - 1
WHERE id = 1;
-- DELETE: remove data
DELETE FROM order_items WHERE order_id = 3;
DELETE FROM orders WHERE status = 'cancelled';

Chapter 7

SELECT Queries

SELECT is the most-used SQL statement. Master filtering, sorting, limiting, and aliasing before moving on to joins. 

-- All columns
SELECT * FROM products;
-- Specific columns with alias
SELECT name AS product_name, price FROM products;
-- Filter with WHERE
SELECT * FROM products WHERE price > 100;
SELECT * FROM products WHERE category_id = 1 AND stock_quantity > 0;
-- Pattern matching
SELECT * FROM customers WHERE email LIKE '%@example.com';
-- Sort results
SELECT * FROM products ORDER BY price DESC;
SELECT * FROM customers ORDER BY last_name ASC, first_name ASC;
-- Limit results
SELECT * FROM products ORDER BY price DESC LIMIT 5;
-- Offset for pagination
SELECT * FROM products ORDER BY id LIMIT 10 OFFSET 20;
-- Distinct values
SELECT DISTINCT status FROM orders;
-- Date filtering
SELECT * FROM orders WHERE order_date >= CURRENT_DATE - INTERVAL '30 days';

Common WHERE operators

=, !=, <>, <, >
Comparison operators.
AND, OR, NOT
Logical operators.
IN, NOT IN
Match a list of values.
BETWEEN
Range check.
IS NULL, IS NOT NULL
Check for missing values.
LIKE, ILIKE
Pattern matching (% wildcard).

Chapter 8

Joins

Joins combine rows from two or more tables based on a related column. They are essential for meaningful reporting. 

-- Inner join: only matching rows
SELECT orders.id, customers.first_name, customers.last_name, orders.order_date
FROM orders
JOIN customers ON orders.customer_id = customers.id;
-- Left join: all customers, even those without orders
SELECT customers.first_name, COUNT(orders.id) AS order_count
FROM customers
LEFT JOIN orders ON customers.id = orders.customer_id
GROUP BY customers.id, customers.first_name;
-- Multiple joins: order details with product and category
SELECT
    o.id AS order_id,
    c.first_name || ' ' || c.last_name AS customer_name,
    p.name AS product_name,
    cat.name AS category,
    oi.quantity,
    oi.unit_price,
    oi.quantity * oi.unit_price AS line_total
FROM orders o
JOIN customers c ON o.customer_id = c.id
JOIN order_items oi ON o.id = oi.order_id
JOIN products p ON oi.product_id = p.id
JOIN categories cat ON p.category_id = cat.id;

Join types

  • INNER JOIN: Only rows that exist in both tables.
  • LEFT JOIN: All rows from the left table, plus matches from the right.
  • RIGHT JOIN: All rows from the right table, plus matches from the left.
  • FULL OUTER JOIN: All rows when there is a match in either table.
  • CROSS JOIN: Cartesian product of both tables.

Chapter 9

Aggregation & Grouping

Aggregate functions summarize data. GROUP BY collapses rows into groups, and HAVING filters those groups. 

-- Total revenue
SELECT SUM(quantity * unit_price) AS total_revenue FROM order_items;
-- Revenue by category
SELECT cat.name AS category, SUM(oi.quantity * oi.unit_price) AS revenue
FROM order_items oi
JOIN products p ON oi.product_id = p.id
JOIN categories cat ON p.category_id = cat.id
GROUP BY cat.name
ORDER BY revenue DESC;
-- Customers with more than one order
SELECT c.first_name, c.last_name, COUNT(o.id) AS order_count
FROM customers c
JOIN orders o ON c.id = o.customer_id
GROUP BY c.id, c.first_name, c.last_name
HAVING COUNT(o.id) > 1;
-- Average order value
SELECT AVG(total) AS avg_order_value
FROM (
    SELECT order_id, SUM(quantity * unit_price) AS total
    FROM order_items
    GROUP BY order_id
) order_totals;
-- Window function: rank products by revenue
SELECT
    p.name,
    SUM(oi.quantity * oi.unit_price) AS revenue,
    RANK() OVER (ORDER BY SUM(oi.quantity * oi.unit_price) DESC) AS rank
FROM products p
JOIN order_items oi ON p.id = oi.product_id
GROUP BY p.id, p.name;

Chapter 10

Subqueries & CTEs

Subqueries let you nest SELECT statements. Common Table Expressions (CTEs) make complex queries readable and reusable within a single query. 

-- Subquery in WHERE
SELECT * FROM products
WHERE category_id = (SELECT id FROM categories WHERE name = 'Electronics');
-- Subquery in SELECT
SELECT name,
       (SELECT COUNT(*) FROM order_items WHERE product_id = products.id) AS times_ordered
FROM products;
-- CTE: monthly revenue
WITH monthly_revenue AS (
    SELECT
        DATE_TRUNC('month', o.order_date) AS month,
        SUM(oi.quantity * oi.unit_price) AS revenue
    FROM orders o
    JOIN order_items oi ON o.id = oi.order_id
    GROUP BY DATE_TRUNC('month', o.order_date)
)
SELECT * FROM monthly_revenue ORDER BY month;
-- Recursive CTE: numbers 1 to 10
WITH RECURSIVE numbers AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM numbers WHERE n < 10
)
SELECT * FROM numbers;

When to use CTEs

  • Break a complex report into named steps.
  • Reuse the same derived table multiple times.
  • Write recursive queries for hierarchical data.

Chapter 11

Indexes & Performance

Indexes speed up reads but slow down writes. They are one of the most important tools for database performance. 

-- Create an index on a frequently filtered column
CREATE INDEX idx_products_category ON products(category_id);
CREATE INDEX idx_orders_customer ON orders(customer_id);
CREATE INDEX idx_customers_email ON customers(email);
-- Composite index for multi-column filters
CREATE INDEX idx_orders_date_status ON orders(order_date, status);
-- Analyze query plans
EXPLAIN ANALYZE
SELECT * FROM products WHERE category_id = 1;
-- Drop an index
DROP INDEX idx_products_category;

Index tips

  • Index columns used in WHERE , JOIN , and ORDER BY clauses.
  • Avoid over-indexing: every index adds write overhead.
  • Use partial indexes for filtered queries.
  • Always verify with EXPLAIN ANALYZE .

Chapter 12

Constraints & Relationships

Constraints protect data integrity. Foreign keys enforce relationships between tables and prevent orphaned rows. 

-- Add a unique constraint
ALTER TABLE customers ADD CONSTRAINT uq_customers_email UNIQUE (email);
-- Add a foreign key
ALTER TABLE orders
ADD CONSTRAINT fk_orders_customer
FOREIGN KEY (customer_id) REFERENCES customers(id)
ON DELETE CASCADE;
-- Add a check constraint
ALTER TABLE products
ADD CONSTRAINT chk_products_price CHECK (price >= 0);
-- Defer foreign key checks until commit
ALTER TABLE order_items
ALTER CONSTRAINT fk_order_items_order DEFERRABLE INITIALLY DEFERRED;

Referential actions

CASCADE
Delete or update related rows automatically.
SET NULL
Set the foreign key to NULL if the parent is deleted.
RESTRICT
Prevent deletion if children exist.
NO ACTION
Like RESTRICT, but checked at commit time.

Chapter 13

Transactions & ACID

A transaction groups multiple operations into a single unit of work. It either completes entirely or rolls back, keeping the database consistent. 

BEGIN;
-- Create an order
INSERT INTO orders (customer_id, status) VALUES (1, 'pending') RETURNING id;
-- Suppose the returned order id is 4
INSERT INTO order_items (order_id, product_id, quantity, unit_price)
VALUES (4, 1, 1, 199.99);
-- Reduce stock
UPDATE products SET stock_quantity = stock_quantity - 1 WHERE id = 1;
-- Commit if everything succeeded
COMMIT;
-- Or undo everything if something failed
-- ROLLBACK;

ACID properties

  • Atomicity: All operations succeed or all are rolled back.
  • Consistency: The database moves from one valid state to another.
  • Isolation: Concurrent transactions do not interfere.
  • Durability: Committed data survives crashes.

Chapter 14

Views & Functions

Views are saved queries that act like tables. Functions let you encapsulate reusable SQL logic inside the database. 

-- Create a view for order summaries
CREATE VIEW order_summary AS
SELECT
    o.id AS order_id,
    c.first_name || ' ' || c.last_name AS customer_name,
    o.order_date,
    o.status,
    SUM(oi.quantity * oi.unit_price) AS total
FROM orders o
JOIN customers c ON o.customer_id = c.id
JOIN order_items oi ON o.id = oi.order_id
GROUP BY o.id, c.first_name, c.last_name, o.order_date, o.status;
-- Query the view
SELECT * FROM order_summary WHERE status = 'delivered';
-- Create a function to calculate order total
CREATE OR REPLACE FUNCTION order_total(order_id INTEGER)
RETURNS DECIMAL AS $$
BEGIN
    RETURN (
        SELECT COALESCE(SUM(quantity * unit_price), 0)
        FROM order_items
        WHERE order_items.order_id = order_id
    );
END;
$$ LANGUAGE plpgsql;
-- Use the function
SELECT id, order_total(id) FROM orders;

Chapter 15

Advanced PostgreSQL

PostgreSQL goes beyond standard SQL. These features are useful for modern applications. 

-- JSON/JSONB support
CREATE TABLE events (
    id SERIAL PRIMARY KEY,
    payload JSONB NOT NULL
);
INSERT INTO events (payload) VALUES
    ('{"event": "login", "user_id": 1}'),
    ('{"event": "purchase", "amount": 199.99}');
SELECT * FROM events WHERE payload->>'event' = 'purchase';
-- Full-text search
CREATE INDEX idx_products_fts ON products USING GIN (to_tsvector('english', name || ' ' || COALESCE(description, '')));
SELECT * FROM products
WHERE to_tsvector('english', name || ' ' || COALESCE(description, '')) @@ to_tsquery('wireless & headphones');
-- Conditional expressions
SELECT name,
       CASE
           WHEN stock_quantity = 0 THEN 'out of stock'
           WHEN stock_quantity < 10 THEN 'low stock'
           ELSE 'in stock'
       END AS stock_status
FROM products;
-- Coalesce: replace NULL with a default
SELECT name, COALESCE(description, 'No description') FROM products;

Chapter 16

Real-World Analytics

Let's answer realistic business questions using the sample store data. 

-- Top 5 customers by lifetime value
SELECT
    c.first_name,
    c.last_name,
    SUM(oi.quantity * oi.unit_price) AS lifetime_value
FROM customers c
JOIN orders o ON c.id = o.customer_id
JOIN order_items oi ON o.id = oi.order_id
GROUP BY c.id, c.first_name, c.last_name
ORDER BY lifetime_value DESC
LIMIT 5;
-- Monthly revenue trend
SELECT
    DATE_TRUNC('month', o.order_date) AS month,
    COUNT(DISTINCT o.id) AS order_count,
    SUM(oi.quantity * oi.unit_price) AS revenue
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
GROUP BY month
ORDER BY month;
-- Products that are low in stock and have been ordered
SELECT p.name, p.stock_quantity, SUM(oi.quantity) AS sold
FROM products p
JOIN order_items oi ON p.id = oi.product_id
WHERE p.stock_quantity < 20
GROUP BY p.id, p.name, p.stock_quantity
ORDER BY sold DESC;
-- Order fulfillment rate
SELECT
    status,
    COUNT(*) AS count,
    ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS percentage
FROM orders
GROUP BY status;
