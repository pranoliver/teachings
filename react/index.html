Chapter 2

What is React?

React is a JavaScript library for building user interfaces. It lets you describe UI as a function of state. When state changes, React efficiently updates only the parts of the page that need to change.

Declarative vs. Imperative UI

Core ideas

  • Components: Small, reusable pieces of UI.
  • Declarative: You say what the UI should look like for each state.
  • One-way data flow: Data moves from parent to child through props.
  • Virtual DOM: React compares updates and applies minimal changes to the real DOM.

JSX

JSX is a syntax extension that lets you write HTML-like code inside JavaScript. It is not HTML — it compiles to regular JavaScript function calls. 

// JSX looks like HTML but lives in JavaScript
function Welcome() {
  const name = "Alex";
  return (

Today is {new Date().toLocaleDateString()}

    

  );
}

JSX rules

  • Return a single root element, or use a fragment <>...</> .
  • Use className instead of class .
  • Use htmlFor instead of for .
  • Curly braces {} embed JavaScript expressions.
  • All tags must be closed: <img /> , <br /> .

Important state rules

  • State updates can be asynchronous and batched.

Chapter 9

Side Effects with useEffect

Side effects are things React does not handle itself: fetching data, subscriptions, timers, or manually touching the DOM. Use the useEffect hook for these. 

import { useState, useEffect } from "react";
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);
  useEffect(() => {
    async function fetchUsers() {
      const response = await fetch("https://jsonplaceholder.typicode.com/users");
      const data = await response.json();
      setUsers(data);
      setLoading(false);
    }
    fetchUsers();
  }, []); // empty dependency array = run once on mount
  if (loading) return

    • 
      ))}
    

  );
}

Dependency array rules

  • useEffect(fn) — runs after every render.
  • useEffect(fn, []) — runs once after mount.
  • useEffect(fn, [x, y]) — runs when x or y changes.
  • Return a cleanup function when subscribing or setting timers.

Chapter 17

Best Practices

Writing clean React code makes apps easier to maintain, test, and scale.

Component design

  • Keep components small and focused.
  • Prefer props over global state.
  • Use descriptive prop and state names.
  • Extract repeated logic into custom hooks.

Performance

  • Always provide stable keys in lists.
  • Memoize expensive computations with useMemo .
  • Avoid inline function definitions in render for heavy subtrees.
  • Split code with lazy loading when apps grow.

Next steps

  • Explore custom hooks to share logic between components.
  • Learn a state library like Zustand or Redux for larger apps.
  • Add React Query or SWR for server state management.
  • Write tests with Vitest and React Testing Library .
